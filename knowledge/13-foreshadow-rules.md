# 13 · 伏笔管理完整规则

伏笔是长篇的骨架。埋得太多会烂尾，埋了不回收会失信，回收时对不上会穿帮。本文件定义伏笔从「埋」到「收」的完整生命周期与校验规则。

---

## 一、7 态状态机

伏笔共 7 个状态，主链路 4 态，另有 2 个分支态与 1 个废弃态：

```
                       ┌──────────────────────────────────────────┐
                       │                                          │
                       ▼                                          │
   ┌──────────┐   ┌──────────────┐   ┌────────────┐   ┌──────────┴──┐
   │ 已埋设   │──►│ 待二次铺垫   │──►│  待回收    │──►│   已回收    │
   │ planted  │   │ foreshadowed │   │pending_    │   │  revealed   │
   └────┬─────┘   └──────┬───────┘   │  reveal    │   └──────┬──────┘
        │                │           └─────┬──────┘          │
        │                │                 │                 ▼
        │                │                 │           ┌───────────┐
        │                │                 │           │ 已回收完成 │
        │                │                 │           │  resolved  │
        │                │                 │           └───────────┘
        │                │                 ▼
        │                │           ┌──────────────┐
        │                └──────────►│  超期未回收   │
        │                            │   overdue     │
        │                            └──────┬───────┘
        │                                   ▼
        │                            ┌──────────────┐
        │                            │   超期预警    │
        │                            │overdue_warning│
        │                            └──────────────┘
        ▼
   ┌──────────┐
   │ 已废弃   │
   │abandoned │
   └──────────┘
```

### 逐态解释

| # | 状态（显示名） | status 键 | 进入条件 | 退出条件 |
|---|----------------|-----------|----------|----------|
| 1 | 已埋设 | `planted` | 伏笔首次在正文出现（氛围、物件、异常现象等） | 再次被提及并加深 → 待二次铺垫；决定放弃 → 已废弃 |
| 2 | 待二次铺垫 | `foreshadowed` | 伏笔被第二次提及 / 被赋予更多线索，但尚未逼近核心真相 | 线索积累到可以回收 → 待回收；也可直接 → 已废弃 |
| 3 | 待回收 | `pending_reveal` | 伏笔已具备回收条件，进入「等待回收」队列 | 在正文中完成揭示 → 已回收；超过计划回收章节 +3 → 超期未回收 |
| 4 | 已回收 | `revealed` | 伏笔核心真相在正文中被揭示 | 所有铺垫要素均已落地、无遗留 → 已回收完成（`resolved`） |
| 5 | 超期未回收 | `overdue` | 当前章节 > `planned_reveal + 3`，且状态仍为待回收 | 用户安排补回收 → 回到待回收；用户决定放弃 → 已废弃 |
| 6 | 超期预警 | `overdue_warning` | 超期未回收持续累积，Claremont 系数 CC > 2，触发 🟠 | 回收若干条使 CC ≤ 2，或明确废弃 |
| 7 | 已废弃 | `abandoned` | 用户明确决定该伏笔不再回收 | 终态，不可逆（如需复活，应新建一条伏笔并注明来源） |

> **与脚本的兼容说明**：`scripts/foreshadow_tracker.py` 的 `VALID_STATES` 为 `planted / foreshadowed / reinforced / pending_reveal / revealed / resolved / abandoned`。本规则的「待二次铺垫」对应 `foreshadowed`（如需强调「二次铺垫」可用 `reinforced`），「已回收」对应 `revealed`，完全落地对应 `resolved`。「超期未回收 / 超期预警」为**运行时告警态**，由追踪器在扫描时派生，通常不直接写入 JSON；若需落盘，使用 `overdue` / `overdue_warning`。

## 二、3 条硬约束

### 硬约束 1 · 提前泄露检查

**规则**：非回收章节不得提及尚未到回收节点的伏笔**核心信息**。

- **允许**：暗示——氛围渲染、情绪铺垫、外围线索（如「他总觉得那枚玉佩在发烫」，但不说明为什么）。
- **禁止**：揭示——核心真相、关键信息（如「玉佩里封着母亲的空间神通」）。

**判定**：若某章不是该伏笔的 `planned_reveal` 章节，正文中却出现了指向其核心真相的明确陈述，即为提前泄露，触发 🔴。

**示例**：
- ✅ 允许：苏浅浅袖口的血色纹路一闪而过，林凡没来得及看清。（外围线索）
- ❌ 禁止：那血色纹路，是苏家禁术「血引」的印记，一旦发作便会反噬宿主。（核心真相）

### 硬约束 2 · 超期提醒

**规则**：两条量化阈值，任一触发即告警。

1. **单条超期（🟡）**：`当前章节 > planned_reveal + 3`，且状态仍为 `pending_reveal` → 标记为 🟡，提醒尽快回收。
2. **整体积压（🟠）**：Claremont 系数 `CC = 已埋设数 − 已回收数`，当 `CC > 2` → 标记为 🟠，说明欠账过多。

> Claremont 系数衡量的是「读者欠账」：埋下的比收回的多太多，读者会失去信任。CC ≤ 2 为健康区间。

**示例**：
- FS-02 计划第 40 章回收，当前已到第 44 章仍未回收 → 🟡（40 + 3 = 43 < 44）。
- 全书已埋设 9 条、已回收 6 条 → CC = 3 > 2 → 🟠。

### 硬约束 3 · 脱节检查

**规则**：回收时必须对照埋设时的摘录，核心要素必须吻合。回收须同时满足以下三个条件，缺一不可：

1. **核心要素吻合**：回收时揭示的内容，与 `core_elements` 中记录的要素一致（不能「换了个人/换了件东西」）。
2. **前文铺垫全部落地**：`setup_refs` 中记录的每一处铺垫，都在回收章得到呼应或解释。
3. **无新增未铺垫设定**：回收章不得引入此前从未铺垫过的新设定来解释伏笔（禁止「机械降神」式补丁）。

**判定**：任一条件不满足 → 🔴，打回修改。

## 三、回收前 4 步自检

在把某条伏笔的状态从 `pending_reveal` 改为 `revealed` 之前，逐条自检：

1. **核对要素**：把本章揭示的内容与台账 `core_elements` 逐项对照，确认完全吻合，没有偷换。
2. **清点铺垫**：遍历 `setup_refs` 列出的每一处铺垫，确认回收章对它们都有交代（呼应、解释或回收）。
3. **排查新设定**：检查回收章是否引入了 `setup_refs` 之外的、此前从未出现的设定；若有，必须要么删除，要么先补铺垫再回收。
4. **检查泄露**：确认回收前没有任何非回收章节提前泄露过本条伏笔的核心信息（回溯检查硬约束 1）。

> 4 步全部通过，方可置为 `revealed`；若全部铺垫要素均已闭环，可进一步置为 `resolved`。

### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 伏笔编号，格式 `FS-xx`，全局唯一 |
| `content` | string | 伏笔的一句话描述（人类可读） |
| `planted_chapter` | int | 首次埋设的章节号 |
| `planned_reveal` | int | 计划回收的章节号；`0` 表示不计划回收（多用于废弃） |
| `status` | string | 当前状态键（见第一节状态机） |
| `core_elements` | string[] | 回收时必须吻合的核心要素清单 |
| `setup_refs` | object[] | 铺垫引用，每项含 `chapter` 与 `note` |
| `abandon_reason` | string \| null | 废弃原因；未废弃时为 `null` |
